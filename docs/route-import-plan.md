# CDO route import — Stage 1 discovery plan

Date: 2026-10-22. Scope: read-only investigation plus this plan. MySQL access succeeded using the existing backend config; credentials are omitted. Only SELECT and SHOW queries were run; no services or containers were started. Existing untracked `AGENTS.MD` was preserved.

## 1. Schema confirmed from live MySQL and `database/schema.sql`

Inspected tables use InnoDB, `utf8mb4_unicode_ci`.

| Table | Columns and nullability | Keys / ordering |
|---|---|---|
| `routes` | id CHAR(36), code VARCHAR(10), name/origin/destination VARCHAR(120), jeepney_type ENUM(Traditional,Modern), status ENUM(Active,Inactive), verification_status ENUM(DRAFT,PENDING_VERIFICATION,VERIFIED,PUBLISHED,DATA_REVIEW_REQUIRED,ERROR), color VARCHAR(9), offline_size_mb DECIMAL(5,2), last_updated_at DATETIME: NOT NULL. description TEXT NULL. inbound_distance_km/outbound_distance_km DECIMAL(5,2) NOT NULL. | PK(id); nonunique indexes on code/status/verification_status/jeepney_type; code NOT NULL and not unique. |
| `terminals` | id CHAR(36), name VARCHAR(120) NOT NULL; note VARCHAR(200) NULL; map_x/map_y DECIMAL(8,4), lat/lng DECIMAL(10,7) NOT NULL, zero defaults. | PK(id); nonunique name index. |
| `route_terminals` | route_id CHAR(36), terminal_id CHAR(36), seq INT all NOT NULL. | PK(route_id,terminal_id); cascading FKs. `seq` stores terminal order. |
| `loading_points` (stops) | id CHAR(36), route_id CHAR(36), name VARCHAR(120), point_type ENUM(loading,unloading), map_x/map_y DECIMAL(8,4), lat/lng DECIMAL(10,7) all NOT NULL; note VARCHAR(200) NULL. | PK(id); route FK cascade; indexes route_id and point_type. No sequence/unique index. |
| `major_roads` (street/road catalog) | id CHAR(36), name VARCHAR(100), both NOT NULL. | PK(id); no unique name constraint. |
| `route_major_roads` | route_id CHAR(36), road_id CHAR(36), seq INT all NOT NULL. | PK(route_id,road_id); cascading FKs; seq orders the links, but same road cannot occur twice for a route. |
| `route_directions` | id CHAR(36), route_id CHAR(36), direction ENUM(Inbound,Outbound), distance_km DECIMAL(5,2), street_sequence TEXT all NOT NULL. | PK(id); unique(route_id,direction); route FK cascade. Street order is encoded in the delimiter-preserving text, conventionally ` | ` separated. It is not a normalized route-street table and has no individual street seq column. |
| `route_geometry` | id CHAR(36), route_id CHAR(36), direction ENUM(Inbound,Outbound), geometry JSON NOT NULL, geometry_status ENUM(PENDING,GENERATED,VERIFIED,ERROR) NOT NULL; generated_at DATETIME NULL. | PK(id); unique(route_id,direction); route FK cascade. No NULL geometry row: absence is represented by no row. |
| `route_path_points` | auto id INT, route_id CHAR(36), seq INT, map_x/map_y DECIMAL(8,4), lat/lng DECIMAL(10,7), all NOT NULL. | PK(id), route FK cascade, index(route_id,seq). |

There is no distinct normalized streets table, route-street link table, or route-stops join: roads are catalogued in major_roads, and stops belong directly to route_id. Direction street order can be kept exactly in `street_sequence`; terminal association order is `route_terminals.seq`; major-road order is `route_major_roads.seq`; stop order is not representable. `route_geometry` has a NOT NULL JSON column, so a missing geometry must mean no geometry row. Existing status fields allow routes to remain pending/review; no needs_geometry boolean exists.

**Blocking schema gap:** `routes.code` is required and capped at 10 characters. A code-less route cannot be represented with its name in `code` as requested; the primary route id is CHAR(36). Do not invent a code. Before implementation, the owner must approve a representation (smallest likely change: nullable code plus backend/UI safe display fallback, or a separate natural-name identifier design). RC/RD and RA/RB fit within 10 characters if explicitly represented as `RC/RD`, `RA/RB`, but that does not prove each is one service.

Closest locality candidates include Lapasan R1/R2/R3; Bugo R1/R2; Cugman R-CUG; Iponan R1/R3/R5; Macabalan R1–R5; Patag Camp Evangelsita–Divisoria; Balulang R-BAL. These fuzzy similarities do not establish identity. No normalized exact source-title match was found. Existing Bugo Agora and Cogon services already have separate records and should remain separate. The table below lists every route, associated terminals, stops, directions and stored street sequences, and geometry presence/status.

Read-only queries run:

```sql
SELECT id,code,name,origin,destination,verification_status FROM routes ORDER BY code,name,id;
SELECT rt.route_id,rt.seq,t.name FROM route_terminals rt JOIN terminals t ON t.id=rt.terminal_id ORDER BY rt.route_id,rt.seq;
SELECT route_id,name,note,point_type FROM loading_points ORDER BY route_id,point_type,name;
SELECT route_id,direction,distance_km,street_sequence FROM route_directions ORDER BY route_id,direction;
SELECT route_id,direction,geometry_status FROM route_geometry ORDER BY route_id,direction;
SELECT rmr.route_id,rmr.seq,mr.name FROM route_major_roads rmr JOIN major_roads mr ON mr.id=rmr.road_id ORDER BY rmr.route_id,rmr.seq;
```

## 3. Geometry and map flow

`backend/scratch/generate_all_route_geometries.js` reads route direction street text, resolves hardcoded street anchors then DB locations then geocoding, requests road geometry via the routing utility (OSRM/OSM flow), and writes route_geometry. It marks geometry VERIFIED and updates route status, so this existing generator is not safe to run for this task: it does not meet the requirement to leave generated route paths unverified. `backend/scratch/generate_verified_route_geometries.js` and admin endpoints for generation/verification also exist; no polylines should be generated during discovery.

Public `/routes` and `/routes/:id` in `backend/src/controllers/routes.js` fetch route records, directions, geometry, major roads ordered by seq, terminals ordered by route_terminals.seq, and stops. Geometry is turned into compatibility path points. Retrofit API definitions are in `android/.../data/remote/OroRutaApi.kt`; the Android `Route` model and `RouteGeometry` live in `domain/models/Models.kt`; `RouteRepository.kt` fetches API data, caches it, and seeds from bundled JSON. `RoutesScreen`, `RouteInfoScreen`, and `MapScreen` render list/detail/map/directions. Admin routes and route maps use `admin-web/src/pages/JeepneyRoutes.tsx`, `RouteMaps.tsx`, DataContext and API. Trace: MySQL -> controller response -> Retrofit serialization -> repository/cache -> Android screens. Missing geometry/stops/coordinates can prevent trip/directions eligibility; zero defaults are not valid invented coordinates. Imported records should stay nonpublished/review until the API trip filters and UI labels are reviewed; directions must exclude them unless verified geometry and required stop data exist.
